# Grok Bot

Use Grok Bots as growing collaborators: set a clear outcome, grant authority that matches the risk, and make completion observable.

Do not use this skill for task partitioning, project records, ordinary engineering execution, reusable skill authoring, or one-off prompt help; use the relevant specialist workflow instead.

## Operating method

1. **Set autonomy boundaries.** State the goal, authority, safety, cost, data, and approval limits. Let bots complete reversible, low-risk work independently; require review or explicit approval before high-impact, irreversible, or sensitive actions.
2. **Close the feedback loop.** Give bots a way to run the real system and observe the user flow. Require them to use the resulting evidence to choose and verify their next action. When a capability is missing, have them investigate and remove the obstacle, then preserve the reusable learning in the repository.
3. **Coach conversationally.** Treat an engineering gap as a learning assignment: ask the bot to research the area, examine successful local examples, and return with an informed approach. Keep the conversation direct rather than adding ritual or oversized prompts.
4. **Delegate recurring work.** Notice tasks with a stable pattern that recur more than once daily. Discuss the pattern, authority, inputs, outputs, and verification with the bots, then hand over the repeatable portion so people can focus on harder judgment.
5. **Repeat essential context daily.** Hold a short daily bot meeting that restates the important workflow, priorities, and guardrails; update the reminder when the operating reality changes.
6. **Learn across bots.** Send bot mistakes through a review loop that identifies the failed decision, contributing context, and a concrete prevention rule. Share the learning with the relevant bots so the same mistake is less likely to recur.

Read the governing rationale in [the Grok Bot principles](references/principles.md).
